# Звукове нагадування про відсутність мережі

Поточний профіль використовує **активний бузер на GPIO21, активний HIGH**.
GPIO19 залишається виходом реле. Призначення та полярність задані в
`boards/esp32c6_rgb8/board.json`: `buzzer_gpio`, `buzzer_active_high`.
Профілі без цих полів не реєструють модуль і не займають GPIO.

Після першого достовірного відкаліброваного звіту про відсутність мережі
(менше 100 В) бузер подає сигнал **200 мс**, потім повторює його кожні
заданий інтервал від початку попереднього сигналу (типово **20 секунд**).
Вебпанель → **Звуковий сигнал** приймає цілі значення **0–86400 секунд**.
**0** вимикає всі сигнали відсутності мережі, включно з першим; активний сигнал
вимикається на наступному tick. Від 100 В — тиша.
Невідомі, некалібровані, недостовірні або застарілі на 2,5 с дані не вважаються
зникненням мережі: сигнал вимикається, цикл скидається. Наступне підтверджене
зникнення запускає новий цикл. Після запуску до першого виміру бузер мовчить.

`BuzzerModule` отримує `MainsReading` у задачі Runtime через `MainsSink`.
`report()` лише оновлює стан; `tick()` керує виходом через вузький `BuzzerOutput`.
Модуль залежить від `mains`, реєструється після нього й не використовує NVS,
окремих задач або callbacks. Тривалість сигналу має точність циклу Runtime:
якщо головна задача затрималася, вимкнення відбудеться на наступному tick.
Пропущені сигнали не відтворюються серією.

У вебпрофілі `NvsBuzzerSettings` реєструється після `nvs` і перед бузером та
web/radio. Він читає `bth_buzzer/interval_s`; відсутній ключ означає 20 с.
Запис і commit виконує HTTP-задача, лише після успішного збереження значення
публікується в чергу на один елемент. Composition root читає копію без очікування
і передає її через `set_interval_seconds` перед tick. Вимкнення Wi-Fi AP не
скидає налаштування. При зміні ненульового інтервалу відлік залишається від
останнього сигналу; увімкнення після 0 запускає сигнал на підтвердженій відсутності.
Якщо commit не вдався, чинний інтервал не змінюється, а подальші записи
відхиляються до повторної ініціалізації; NVS не стирається.
HTTP завершується до видалення черги та закриття NVS.

`EspBuzzer` у `bth_platform` встановлює неактивний рівень перед увімкненням
виходу GPIO. `stop` і `deinit` вимикають бузер, включно з відкатом частково
невдалого запуску. Після очищення вихід залишається в неактивному рівні.

Host-тести перевіряють поріг, тривалість, період, повернення мережі, втрату
даних, 64-бітний час, повторний запуск і відкат помилок. Компіляція та host-тести
не підтверджують фізичну роботу бузера.
