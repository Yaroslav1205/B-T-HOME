# OLED SSD1306

Для вікна корпусу **19 мм** при ширині дисплея **23 мм** усі сторінки
стиснено по горизонталі та посунуто вправо на **3 мм (17 пікселів)**.
Вміст займає не більше **105×32 пікселів**, колонки **17–121**.
Ліві 17 і праві 6 колонок завжди порожні.
Висота символів збережена, тонкі штрихи об’єднуються під час стискання.

У Matter-режимі після сторінки реле додається **IP**: поточна IPv4-адреса
одним рядком, наприклад `192.168.1.123`, на 3 секунди. Навіть адреса з 15
символів повністю вміщується на 128×32. У браузері відкрийте `http://<адреса>`.
Якщо Wi-Fi відключений або адреси ще немає, показується `---`.

Параметр `show_ip` вмикає сторінку; `report_ipv4` копіює чотири октети
у порядку показу, нульовий масив означає відсутню адресу. Composition root
раз на секунду поза `Runtime::tick` читає знімок через `MatterModule::ipv4_address()`.
Адаптер перевіряє підключення STA та стан інтерфейсу, щоб не показувати стару
DHCP-адресу після відключення. OLED залишається незалежним від ESP-IDF;
callbacks не звертаються до нього. Під час `start` адреса очищується.

За підключеного модуля оцінки акумулятора сторінка DC при відсутності мережі
показує `-11.7V=12:05` компактними цифрами: напруга та залишок годин/хвилин.
За наявності мережі зберігається великий показ `+12.8V`. Невідомий час —
`--:--`, понад 99 годин — `>99:59`; невідомий стан мережі позначається `?`.
[Параметри моделі й збереження оцінки](../../docs/BATTERY.md).

Після сторінок напруги застосунок додає два екрани історії мережі по 3 с:
**ЗАРАЗ** (поточний період) та **БУЛО** (попередній). `+` означає наявність
живлення, `−` — відсутність. Час показується цифровими сегментами у форматі
`DDD:HH:MM` (дні:години:хвилини); години — `00–23`, після 999 днів показ
обмежується значенням `999:23:59`. Невідомі/застарілі дані позначаються рисками.
Параметр конструктора `show_history` додає ці екрани після `page_count`
сторінок напруги; історія надходить через `MainsReading`, без доступу до ADC з OLED.

У профілі `esp32c6_rgb8` увімкнено **автоматичну перевірку OLED** за адресою
`0x3C` на GPIO23/15 (SDA/SCL) під час запуску (`oled.enabled: true`). Без відповіді (NACK або
таймаут 100 мс) прошивка друкує попередження, звільняє I²C та працює без OLED.
LED, вимірювання мережі й вебкерування продовжують запуск. Таймаут може також
означати проблему шини/підтяжок; причина вказана в журналі.
Після підключення дисплея перезапустіть плату. Перевіряється ACK адреси,
а не ідентифікатор контролера: на цій адресі має бути саме SSD1306.
`oled.enabled: false` повністю вимикає перевірку й використання дисплея.

Модуль підтримує OLED SSD1306 128×32. При запуску показує заставку **B-T HOME**
під час двосекундного блимання LED. Після заставки починається показ мережі
на повні 3 секунди, потім DC. Вимірювання надходять і під час заставки.
Дисплей показує виміряну RMS-напругу мережі
з одним десятковим знаком, наприклад **~230.5V**: семисегментні цифри заввишки 32 пікселі, десяткова
крапка й літера V. Напис займає до 105×32 пікселів без обрізання, з проміжками
між символами; висота цифр максимальна для цього екрана.
Показ оновлюється за секундним звітом `MainsModule`; незмінний кадр не передається
повторно. Перед мережею показується `~`, перед батареєю — `+`.
Початкові нулі приховані; приклади: `~230.5V`, `+3.5V`, `+29.8V`, `+0.0V`.
До першого результату, без калібрування, за недійсних даних, поза діапазоном
0–999,9 В або через 2,5 с без нового звіту показуються риски зі знаком
відповідної сторінки: `~---.-V` або `+---.-V`.
Коефіцієнт калібрування типово дорівнює нулю: [налаштування](../../docs/MAINS.md).

У профілі з DC-входом покази чергуються **мережа → середня мережа → DC → ЗАРАЗ → БУЛО**, по **3 секунди**.
Середня мережа — ковзне середнє останніх 60 достовірних секундних RMS-вимірів
від 100 В. За підтвердженої відсутності мережі (нижче 100 В) середнє заморожене
на значенні перед вимкненням, а після повернення мережі вікно продовжується.
Після недостовірного виміру вікно починається заново. Без попередніх вимірів
наявної мережі середнє недоступне. Його знак `=` відрізняє сторінку від поточної
мережі `~`. Свіжі звіти про відсутність підтримують показ збереженого середнього;
якщо самі звіти перестали надходити, діє звичайний контроль застарілих даних.
Після запуску першою є мережа.
`OledModule` приймає кількість сторінок напруги (1–8); `report_value` оновлює явний індекс.
Нові сторінки напруги додаються у composition root. [DC-вхід](../../docs/DC_INPUT.md).

| Контакт дисплея | Підключення |
| --- | --- |
| VCC | 3,3 В |
| GND | GND плати |
| SDA | GPIO23 |
| SCL | GPIO15 |

У цьому профілі консоль використовує вбудований USB Serial/JTAG
(`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`). Термінал підключайте до native USB плати.

I²C: порт **0**, частота **100 кГц**, внутрішні підтяжки ввімкнені.
Адреса в ESP-IDF — **0x3C** (7 біт); **0x78** — адресний байт запису на шині,
його формує драйвер. Контраст — **0x8F**, окремий RESET не використовується.
Дисплей має забезпечувати апаратний reset власною схемою модуля при подачі живлення.
Параметри зберігаються в `boards/esp32c6_rgb8/board.json`, у секції `oled`.
Generic-профілі без цієї секції не реєструють OLED і не займають I²C/GPIO.

`bth_oled` містить незалежний від ESP-IDF рендерер і модуль життєвого циклу.
Власний растровий шрифт не потребує бібліотек або файлів шрифтів. Буфер — 512 байтів,
чотири сторінки по 128 колонок. `EspOledI2c` у `bth_platform` володіє шиною та
пристроєм; зараз ця шина виділена дисплею.

`init` створює шину й пристрій та перевіряє адресу через `OledTransport::probe`.
Без відповіді ресурси одразу звільняються, а `start`/`tick` працюють без I/O.
Для знайденого дисплея `start` налаштовує SSD1306, записує весь кадр
при вимкненому дисплеї та вмикає його. Для 32 рядків задано multiplex `0x1F`,
COM pins `0x02`, горизонтальну адресацію, внутрішній charge pump. Команди звірено з
[даташитом Solomon Systech](https://www.electronicscomp.com/datasheet/ssd1306-datasheet.pdf).
Всі I²C-передачі синхронні з таймаутом 100 мс на передачу; їх немає в `tick`.
У `start` запускається задача адаптера для оновлень. `tick` лише копіює новий
кадр у чергу на один елемент (новіший замінює ще не оброблений) і перевіряє
помилку передачі. Задача задає адресне вікно й передає 512 байтів кадру;
очікування I²C не затримує вимірювання ADC. `report` викликається тільки з
задачі Runtime й копіює `MainsReading`, без I/O та звернень до Runtime.

`stop` завершує задачу оновлень перед вимкненням дисплея; `deinit` звільняє
чергу, семафор, пристрій і шину, також після часткової
помилки. Відсутність відповіді на початкову перевірку є штатним режимом.
Інші помилки створення ресурсів або передачі вже виявленому дисплею залишаються
фатальними: Runtime відкочує застосунок. Автоматичних reboot чи стирання NVS немає.
Періодичне опитування підключення не реалізоване.

Host-тести перевіряють рисунок цифр, крапку, межі кадру, конфігурацію SSD1306,
роботу без дисплея, його появу/зникнення між запусками, очищення ресурсів,
повторний запуск і відкат на кожному етапі передачі. Компіляція та ці тести
не замінюють перевірку живлення, орієнтації та зображення на фізичному дисплеї.
# Сторінка стану реле

Після сторінок напруги та часу в циклі з’являється **РЕЛЕ** зі станом
**УВІМК** або **ВИМК**, також на 3 секунди. Зміна стану під час показу цієї
сторінки оновлює її без перезапуску циклу. Якщо стан виходу невідомий, показується `---`.
Це підтверджений програмний стан виходу, а не вимірювання контактів реле.

Параметр конструктора `show_relay` додає сторінку в кінець циклу.
Composition root перед кожним `Runtime::tick` передає копію `RelayService::snapshot()`
через `report_relay`; OLED не залежить від ESP-IDF чи relay worker.
Після повторного запуску стан невідомий до нового звіту.
