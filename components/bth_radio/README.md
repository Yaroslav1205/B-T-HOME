# Перемикання радіорежимів

Коротке натискання BOOT циклічно вибирає **AP → STA → Zigbee → AP**.
Утримання від 3 с із відпусканням у Zigbee запускає сполучення; у Wi-Fi не має дії.
`RadioModeStore` зберігає вибір через NVS-адаптер `NvsAccessStore`, ключ
`bth_access/radio_mode` (1/2/3); відсутній запис означає AP. Некоректний запис або
помилка сховища повертає помилку, без автоматичного стирання.
`toggle()` спершу зупиняє дочірні модулі, потім робить commit вибору та запускає
нову групу. `WifiModeControl` задає AP/STA до ініціалізації Wi-Fi.

`StationRetry` обмежує кожну спробу підключення разом із DHCP до 15 с і чергує
два заповнені слоти. Успішне підключення припиняє спроби, втрата зв’язку
відновлює цикл із наступного слота. Порожні слоти пропускаються; без обох
мереж пристрій чекає перемикання BOOT. Нових задач і власних callbacks немає.

`RadioMode` — portable-модуль з явними посиланнями на Zigbee, Wi-Fi та веб.
Одночасно володіє lifecycle лише Zigbee або групи Wi-Fi → веб. Залежності
`nvs`, `access`, `relay` належать зовнішньому Runtime й не зупиняються при
перемиканні. Об'єкти дочірніх модулів мають існувати довше за `RadioMode`;
їх не можна додатково реєструвати у Runtime чи запускати окремо.

`toggle()` викликає лише задача-власник поза `tick`: завершення мережевих
задач може потребувати очікування. Помилка повертається власнику, який
зупиняє Runtime. Очищення включає частково ініціалізовану/запущену дитину.

`BootGesture` отримує логічний стан натискання й монотонний час. Брязкіт —
40 мс; коротке натискання — від 50 мс, довге — від 3000 мс. Подія формується
лише після відпускання. Затиснута при старті кнопка ігнорується до відпускання;
пауза опитування понад 250 мс скидає поточний жест, щоб не створити випадкову дію.

Host-тести: `tests/host/test_radio.cpp`. Апаратний адаптер — `BootButton`
у `bth_platform`; GPIO та полярність задаються профілем плати.

Перевірка 17.10.2026: host-тести циклу трьох режимів, відновлення вибору,
помилок сховища, відкату lifecycle та чергування мереж пройшли. Окремі тести
`test_access_store.cpp` перевіряють реальний NVS-адаптер із підставним сховищем:
міграцію v1 → v2, незмінність облікового запису, збереження слотів і режиму,
пошкоджені записи та помилки commit. Браузерний тест перевіряє передачу основної
й резервної мережі та очищення полів паролів. Фізичне підключення до роутерів,
повторні перемикання Wi-Fi/Zigbee та відновлення після вимкнення живлення на
платі ще не перевірені; прошивання не виконувалося.
