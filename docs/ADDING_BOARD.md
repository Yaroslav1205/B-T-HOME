# Додавання плати

Профіль описує **конкретну апаратну конфігурацію**, а `target` — сімейство чипа.
Дві різні плати з ESP32-C6 можуть мати різні GPIO, flash, дисплеї та активні рівні.
Профілі `generic_*` призначені для перевірки компіляції та діагностичної прошивки.

## Новий профіль

1. Створіть `boards/my_c6_board/board.json`:

   ```json
   {
     "name": "My ESP32-C6 board",
     "target": "esp32c6"
   }
   ```

2. Додайте `boards/my_c6_board/sdkconfig.defaults` з перевіреними параметрами
   flash, консолі, пам'яті та периферії. Навіть якщо перевизначень немає, залиште
   файл із пояснювальним коментарем.
3. Коли потрібні GPIO, додайте типізовані поля профілю, їх читання в
   `cmake/board.cmake` та генерацію в `components/bth_board/board_config.hpp.in`.
   Перевіряйте обов'язковість і діапазони значень. Для непідтримуваної можливості
   використовуйте явний прапорець/відсутність, а не випадковий GPIO за замовчуванням.
4. Передавайте апаратні параметри адаптерам у `main/application.cpp`.
   Логіка модулів не повинна перевіряти назви dev board чи `CONFIG_IDF_TARGET_*`.
5. Зберіть новий профіль і додайте його до CI, якщо він має підтримуватися постійно:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\idf.ps1 -Board my_c6_board
   ```

`build/my_c6_board/` і його `sdkconfig` незалежні від решти профілів. Окремо запускати
`set-target` не потрібно: target читається з профілю. Конфлікт між профілем і target
зупиняє конфігурацію з поясненням.

## Інші мікроконтролери

Інші ESP32, підтримані вибраною ESP-IDF, додаються аналогічно. Наявність профілю ще
не означає, що конкретна периферія або бездротовий протокол підтримуються цим чипом.

Для іншого сімейства, наприклад STM32, переноситься portable ядро та логіка модулів.
Потрібні власні драйвери/адаптери, точка входу та система firmware-збірки. Профіль
ESP-IDF сам по собі такого перенесення не виконує.

## Профіль RGB на GPIO8

`esp32c6_rgb8` — поточний профіль за замовчуванням, ESP32-C6 з адресним RGB LED
на GPIO8 за даними користувача. Поле `rgb_led_gpio` у `board.json` вмикає
можливість; відсутнє поле генерує `board::rgb_led_gpio = -1` і вимикає модуль.
Адаптер перевіряє придатність GPIO для виводу до його налаштування.
Підтримується WS2812-сумісний протокол. Журнал фізичного пристрою підтвердив
flash 4096 КБ: profile defaults задають 4 MB. PSRAM не додається.

Для реле профіль містить `relay_gpio` та обов'язковий boolean `relay_active_high`.
У поточному профілі це GPIO3 і `true`, підтверджені користувачем. CMake відхиляє
спільний GPIO реле та RGB; адаптер перевіряє придатність GPIO для виводу.
Відсутній `relay_gpio` означає недоступне реле, а не GPIO за замовчуванням.

Кнопка BOOT задається полями `boot_button_gpio` та обов'язковим boolean
`boot_button_active_low`. Для `esp32c6_rgb8` користувач підтвердив GPIO9;
штатна BOOT активна LOW, адаптер вмикає підтяжку вгору. За відсутності поля
GPIO дорівнює `-1`; код не вгадує пін. CMake перевіряє конфлікти з реле,
RGB, ADC та ввімкненим OLED. Профіль із Zigbee потребує налаштованої BOOT
для переходу до Wi-Fi. [Поведінка кнопки](ZIGBEE.md#кнопка-boot-і-режим-налаштування).

## OLED у профілі

Секція `oled` описує дисплей; `enabled: false` залишає його вимкненим,
не займаючи I²C/GPIO. У поточному профілі ввімкнено перевірку наявності при запуску:

```json
"oled": {
  "enabled": true,
  "controller": "ssd1306",
  "width": 128,
  "height": 32,
  "port": 0,
  "sda": 16,
  "scl": 17,
  "speed_hz": 100000,
  "address": 60,
  "contrast": 143,
  "internal_pullups": true,
  "reset_gpio": -1
}
```

JSON використовує десяткові числа: `60` = `0x3C`, `143` = `0x8F`.
За `enabled: true` відсутній дисплей автоматично пропускається. Після фізичного
підключення достатньо перезапуску плати. Поле має бути boolean; для сумісності
його відсутність означає `true`.
Поточний адаптер підтримує SSD1306 128×32 без окремого RESET. CMake перевіряє
параметри й конфлікти SDA/SCL з реле та LED; придатність GPIO і порту для
конкретного чипа перевіряє адаптер/ESP-IDF. Без секції `oled` генерується
`board::oled_enabled = false`, ресурси дисплея не створюються.
[Підключення та робота OLED](../components/bth_oled/README.md).

## Вхід DC 3–30 В

Опційна секція `dc_input` містить `gpio`, `upper_ohms`, `lower_ohms`.
Поточний адаптер підтримує ESP32-C6 зі вже призначеним `mains_adc_gpio`:
один драйвер ADC обслуговує обидва канали. CMake відхиляє зайнятий GPIO,
непридатний канал, непозитивні опори та коефіцієнт дільника менше 13.
Без цієї секції `board::dc_adc_gpio = -1`, DC-модуль і його OLED-сторінка
не реєструються. [Схема та приклад профілю](DC_INPUT.md).
