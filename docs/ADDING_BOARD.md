# Додавання плати

Профіль описує **конкретну апаратну конфігурацію**, а `target` — сімейство чипа.
Дві різні плати з ESP32-C6 можуть мати різні GPIO, flash, дисплеї та активні рівні.
Профілі `generic_*` призначені для перевірки компіляції та діагностичної прошивки.

## Новий профіль

1. Створіть `boards/my_c6_board/board.json`:

   ```json
   {
     "name": "My ESP32-C6 board",
     "target": "esp32c6"
   }
   ```

2. Додайте `boards/my_c6_board/sdkconfig.defaults` з перевіреними параметрами
   flash, консолі, пам'яті та периферії. Навіть якщо перевизначень немає, залиште
   файл із пояснювальним коментарем.
3. Коли потрібні GPIO, додайте типізовані поля профілю, їх читання в
   `cmake/board.cmake` та генерацію в `components/bth_board/board_config.hpp.in`.
   Перевіряйте обов'язковість і діапазони значень. Для непідтримуваної можливості
   використовуйте явний прапорець/відсутність, а не випадковий GPIO за замовчуванням.
4. Передавайте апаратні параметри адаптерам у `main/application.cpp`.
   Логіка модулів не повинна перевіряти назви dev board чи `CONFIG_IDF_TARGET_*`.
5. Зберіть новий профіль і додайте його до CI, якщо він має підтримуватися постійно:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\idf.ps1 -Board my_c6_board
   ```

`build/my_c6_board/` і його `sdkconfig` незалежні від решти профілів. Окремо запускати
`set-target` не потрібно: target читається з профілю. Конфлікт між профілем і target
зупиняє конфігурацію з поясненням.

## Інші мікроконтролери

Інші ESP32, підтримані вибраною ESP-IDF, додаються аналогічно. Наявність профілю ще
не означає, що конкретна периферія або бездротовий протокол підтримуються цим чипом.

Для іншого сімейства, наприклад STM32, переноситься portable ядро та логіка модулів.
Потрібні власні драйвери/адаптери, точка входу та система firmware-збірки. Профіль
ESP-IDF сам по собі такого перенесення не виконує.
