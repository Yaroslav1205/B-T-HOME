# Графік відключень Чернівціобленерго

У звичайній Wi-Fi/Zigbee-збірці вебпанель → **Графік відключень** дозволяє
задати групу **1–12**. Типово — **2**. **0 вимикає запити та сторінку OLED**.
Вибір зберігається в NVS (`bth_outages/group`) і застосовується без перезапуску.
Matter-збірка поки не підключає цю функцію; її панель прихована.

Запити виконуються лише у режимі **Wi-Fi-клієнта з отриманою IP-адресою**.
У точці доступу та Zigbee запитів немає. Перший запит — після підключення
та отримання коректного часу; наступні — кожні **5 хвилин**, також після помилок.
Зміна групи, повторне підключення та зміна дати запускають нову спробу.
Вже розпочатий запит при вимкненні/зміні групи припиняється після повернення
поточної мережевої операції; його результат для іншої групи не публікується.

## Джерело й достовірність

Джерело — публічна HTTPS-сторінка [офіційного каналу](https://t.me/s/oe_cv_ua).
Токен Telegram та особистий обліковий запис не потрібні. Сайт обленерго під час
перевірки повертав HTTP 403. Канал публікує текстові **графіки заживлення**:
це години **наявності** електрики. Прошивка обчислює доповнення цих інтервалів
у межах доби й показує саме планові **відключення**.

Розпізнаються датовані публікації «графік заживлення», секції «Група N»,
інтервали `00:00 - 16:00`, `з 18:30`, повідомлення про електропостачання
без обмежень для окремої групи або всіх груп. Вибирається остання розпізнавана
публікація для **сьогоднішньої дати** у завантаженій сторінці.
Нова публікація для цієї дати з пошкодженою секцією групи скасовує попередній
результат. Завтрашній графік не замінює сьогоднішній.

Це розбір публічної сторінки, а не гарантований API. Зміна верстки, формату,
публікація тільки зображення або відсутність сьогоднішнього графіка серед
останніх повідомлень може залишити пристрій без даних. Прочитаний графік
чинний для показу не довше **15 хвилин** від успішного отримання; після
втрати Wi-Fi він одразу позначається застарілим. Кеш не записується у flash.

Час синхронізується через SNTP (`pool.ntp.org`), також при групі 0 для перевірки
TLS-сертифікатів OTA. До отримання часу HTTPS-запит
не виконується. Використано правило київського часу
`EET-2EEST,M3.5.0/3,M10.5.0/4`; при зміні державних правил його слід оновити.
HTTPS перевіряє сертифікат через bundle ESP-IDF, перенаправлення вимкнені.

## OLED

Після IP додається сторінка **ГРАФІК 02**, на 3 секунди:

- `16:00-18:30` — поточний або найближчий інтервал планового відключення;
- **ДАЛІ БЕЗ ВІДКЛ** — до кінця сьогоднішньої доби більше немає планових відключень;
- **НЕМАЄ ДАНИХ** — графік не отримано, не розпізнано, група/дата змінилася;
- **ЗАСТАРІЛО** — втрачено Wi-Fi або минуло 15 хвилин без оновлення.

План не змінює виміряний стан AC і не керує реле чи бузером.
Аварійні відключення й оперативні зміни можуть відрізнятися від графіка.

## Реалізація й перевірка

`bth_outages` містить незалежний від ESP-IDF потоковий парсер, перевірку
актуальності та обмеження частоти запитів. HTML обмежено 256 КіБ, один текст
повідомлення — 8 КіБ. Перевищення меж не дає часткового успішного результату.
`NvsOutageSettings` передає налаштування через чергу на один елемент;
HTTP записує NVS перед публікацією нового значення.

`OutageService` працює в окремій задачі зі стеком 8 КіБ. Знімок результату
надходить власнику Runtime через чергу на один елемент. HTTP/TLS і SNTP
не виконуються в `tick`. Таймаут мережевої операції — 5 с; цикл читання
також перевіряє загальний бюджет 20 с між операціями. Зупинка чекає завершення
поточної операції, очищення HTTP-клієнта та SNTP. Перед перемиканням радіо
composition root зупиняє/join-ить задачу; після перемикання запускає її знову.
Збої мережі, HTTP та парсингу не зупиняють застосунок.

Основний профіль із усіма ввімкненими модулями займає **16 слотів Runtime**.
Наступне розширення потребує перегляду складу; автоматичного збільшення ліміту немає.

Host-тести перевіряють межі групи, помилки NVS/commit, розбір частинами,
ревізії, дати, інтервали, прострочення, перепідключення та вимкнення сторінки OLED.
Браузерний тест перевіряє налаштування й помилку збереження.
Окремо перевірено парсер на завантаженій офіційній сторінці.
Ці перевірки та збірка не замінюють фізичну перевірку HTTPS/SNTP і показу на платі.
